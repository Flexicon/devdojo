# AGENTS.md — devdojo

Personal practice repo. Agents here generate and review LeetCode-style
practice problems; the human solves them. Follow these conventions so the
skills stay consistent.

## Layout

- `.agents/skills/` — repo skills: `new-dojo` (scaffold topics), `spar`
  (generate problems), `sensei` (review solutions). `.claude/skills` is a
  symlink here.
- Every other top-level directory is a **topic**: a self-contained practice
  project (`rust/`, `dsa-go/`, ...).

## Topic anatomy

Each topic dir contains:

- `TOPIC.md` — the contract. Frontmatter: `topic`, `kind`
  (language | framework | concept), `level` (beginner | intermediate |
  advanced), `created`, `test_all`, `test_one`, and `problem_glob`. Sections:
  Goals, Conventions, Progress log. Skills read and update it; keep it
  accurate.
- A minimal toolchain whose test runner works (cargo, go test, pytest,
  vitest).
- Test commands in frontmatter: `test_all` runs the topic, `test_one` runs a
  problem using `{problem}`, and `problem_glob` identifies the problem file.
  These let the root `./dojo` CLI run topics uniformly without per-topic
  scripts.
- Problems generated by `spar`, solved by the human, reviewed by `sensei`.

## Problem layout (canonical defaults)

Slug: `pNNN-kebab-name`, NNN a per-topic sequence. Every problem = statement +
unimplemented stub + failing tests, runnable one-problem-per-command.

| Language   | Problem location                                            | Statement           | Per-problem test command      |
| ---------- | ----------------------------------------------------------- | ------------------- | ----------------------------- |
| rust       | `src/problems/pNNN_slug.rs` (register in `src/problems/mod.rs`), tests colocated in `#[cfg(test)]` | doc comment atop file | `cargo test pNNN`          |
| go         | `problems/pNNNslug/slug.go` + `slug_test.go`                | doc comment atop file | `go test ./problems/pNNNslug/` |
| python     | `problems/pNNN_slug.py` + `tests/test_pNNN_slug.py`         | module docstring      | `pytest tests/test_pNNN_slug.py` |
| typescript | `problems/pNNN-slug.ts` + `problems/pNNN-slug.test.ts`      | JSDoc atop file       | `npx vitest run pNNN`          |

A topic's Conventions section overrides these when it differs.

## Root CLI (`./dojo`)

- `dojo bout` — run every topic's tests, print a pass/fail summary (nonzero
  exit if any topic fails).
- `dojo bout <topic>` — one topic.
- `dojo bout <topic> <problem>` — one problem; `p1`, `p0001`, and
  `p0001-two-sum` are all accepted.

Discovery: any top-level dir with `TOPIC.md` is a topic; topics with
`test_all` configured are runnable. Adding a language means filling in the
three test fields in the new topic (via `new-dojo`), never editing the root
script. The CLI is a single dependency-free Node script; keep topic-specific
knowledge in TOPIC.md rather than adding language branches to `dojo`.

## Hard rules for agents

- **Never solve a problem** when generating or reviewing — stubs only. During
  review, edit the user's solution only on explicit request.
- Generated tests must fail against the stub for the right reason
  (unimplemented), never from harness/syntax errors.
- After generating or reviewing, update the topic's progress log
  (`open` / `solved` + notes).
- Minimal scaffolding: no CI, no linters, no extra config unless asked.
